## Docker compose v1 兼容性第二次修复

用户再次报错：`'./docker-compose.yaml' is invalid because: Unsupported config option for services: 'layout-server' / Unsupported config option for volumes: 'paddlex-models'`——典型 docker-compose v1 报错。根因：文件无 `version:` 键时 v1 按旧格式解析，顶层 `services`/`volumes` 被当作服务名，其内部键被视为未知配置项。

修复：加 `version: "3.8"`；移除 v1 不支持的 `profiles`（vllm 服务整体注释保留，需要时取消注释）；README/.env.example 同步（删掉 --profile vllm 说明）。本机 v5.1.4 校验通过（version 仅 obsolete 警告）。另建议用户优先升级 docker compose v2。

## Docker compose 插值兼容性修复

用户 `docker-compose build` 报错 `Invalid interpolation format for "layout-server" option in service "services": "${HOST_PORT:-8399}:8399"`——旧版 docker-compose（v1 Python，错误格式即 `for "X" option in service "Y"`）不支持 `${VAR:-default}` 带默认值插值。

修复：compose 文件彻底移除 `:-` 插值——端口硬编码 `"8399:8399"`，常规配置写明文（VLLM_SERVER_URL=http://vllm:8000/v1、AI_STUDIO_MODEL、JWT_SECRET 等），仅保留最基础的 `${AI_STUDIO_TOKEN}` 透传（空值=本地模式，语义正确，全版本兼容）。.env.example / README 同步更新（注明其余配置直接改 compose）。本机 v5.1.4 验证：无 token / 有 token 两种场景渲染均正确。

新增 Docker 部署支持：

- **Dockerfile**：python:3.12-slim 基础镜像，装 libgl1/libglib2.0-0 等 cv2 运行库；先拷 pyproject + server.py 再 `pip install -e .` 利用层缓存；非 root 用户（app，uid 1001）；env 中 UPLOAD_DIR=/app/data/uploads、USER_DB_PATH=/app/data/user.json、模型缓存 HOME=/home/app/.paddlex。
- **docker-compose.yaml**：`layout-server` 服务（端口 ${HOST_PORT:-8399}:8399，卷 layout-data 持久化 uploads/user.json、paddlex-models 持久化模型缓存；healthcheck 用 TCP 探测——因为整个 app 全局挂了 verify_token，/health 也要 Bearer 鉴权）；可选 `vllm` 服务（profile: ["vllm"]，需 NVIDIA GPU，`docker compose --profile vllm up -d`）。
- **.dockerignore**：排除 .venv/uploads/tests/.workbuddy 等；**.env.example**：二选一模式（AI_STUDIO_TOKEN / VLLM_SERVER_URL）。
- **关键约束**：所有接口（含 /health）都在 JWT 鉴权下 → healthcheck 不能用 HTTP 探活；admin token 启动时打印在 stdout（`docker compose logs | grep "Admin token"`）；JWT_SECRET 改动会使旧 token 失效。
- 验证：`docker compose config` 通过（本机 Docker Compose v5.1.4）；`pip install -e . --no-deps` 无 setup.py 可正常安装（PEP 621 + tool.setuptools.py-modules）；59 测试全通过。

## AI Studio 托管 API 模式（AI_STUDIO_TOKEN 分流）

为 paddleocr-vl-layout-server 增加 AI Studio 托管 API 模式：

- **环境变量**：`AI_STUDIO_TOKEN`（配置后启用托管模式）、`AI_STUDIO_MODEL`（默认 PaddleOCR-VL-1.6）、`AI_STUDIO_JOB_URL`、`AI_STUDIO_POLL_INTERVAL`、`AI_STUDIO_TIMEOUT`、`AI_STUDIO_REQUEST_TIMEOUT`。
- **分流逻辑**：`process_single_file()` OCR 分支（扫描件 PDF + 图片）配置 token 时走 `process_with_aistudio()`，无需 VLLM_SERVER_URL；文本 PDF / Office 文件仍走本地 markitdown。
- **关键函数**：`process_with_aistudio`（提交 job → 轮询 state → 下载 JSONL）、`_merge_aistudio_results`（JSONL 每行 result 与本地 /layout-parsing 格式一致，合并 layoutParsingResults/preprocessedImages/dataInfo）、`_resolve_image_value`（AI Studio 返回的 http 图片 URL 下载后转 base64 data URL，保证响应与本地一致）、`_sniff_file_suffix`（base64 上传时按魔数嗅探真实后缀）。
- **依赖**：pyproject.toml 增加 `requests>=2.25`。
- **测试**：新增 tests/test_aistudio.py（14 例），全套 59 例通过。
